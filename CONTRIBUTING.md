# 🤝 Contributing to Skill Bridge

Thank you for contributing to **Skill Bridge – Local Worker Connector**.

This project follows a structured workflow to ensure clean code, proper collaboration, and smooth development.

---

# 📋 Development Workflow

1. Pull the latest changes from the `main` branch.
2. Create your own feature branch.
3. Complete your assigned task.
4. Test your changes locally.
5. Commit your work with a meaningful commit message.
6. Push your branch to GitHub.
7. Create a Pull Request (PR).
8. Wait for review before merging.

> **Never push directly to the `main` branch.**

---

# 🌿 Branch Naming Convention

Use the following branch naming format:

### Frontend

```
frontend/<feature-name>
```

Examples:

```
frontend/homepage-ui
frontend/navbar-update
frontend/worker-profile
```

---

### Backend

```
backend/<feature-name>
```

Examples:

```
backend/job-api
backend/recommendation-api
backend/auth-improvements
```

---

### Research / Technical Lead

```
research/<feature-name>
```

Examples:

```
research/ai-recommendation
research/trust-score
```

---

# 📝 Commit Message Convention

Use clear and descriptive commit messages.

Examples:

```
feat: add worker profile page

fix: resolve login validation issue

docs: update project documentation

style: improve homepage UI

refactor: optimize worker controller
```

---

# 📂 Folder Responsibilities

## Frontend Developer

May work inside:

```
client/
```

Examples:

- Components
- Pages
- Styling
- API integration
- Forms

---

## Backend Developer

May work inside:

```
server/
```

Examples:

- Controllers
- Routes
- Models
- Middleware
- APIs

---

## Technical Lead

Responsible for:

- Project Architecture
- Code Review
- Research Features
- Merge Requests
- Repository Management
- Documentation

---

# ✅ Before Creating a Pull Request

Ensure:

- Project builds successfully
- No console errors
- No unnecessary files committed
- Code is properly formatted
- Feature works as expected

---

# 🚫 Do Not

- Push directly to `main`
- Commit `.env`
- Commit `node_modules`
- Modify another member's assigned feature without discussion
- Delete existing functionality without approval

---

# 🧪 Testing Checklist

Before pushing:

- Application starts successfully
- Backend runs without errors
- Frontend runs without errors
- New feature is tested
- Existing functionality is not broken

---

# 🔍 Code Review Process

Every Pull Request will be reviewed by the Technical Lead.

The review will check:

- Code quality
- Functionality
- Performance
- Readability
- Project structure

Only after approval should the branch be merged.

---

# 💬 Communication

If you are blocked:

1. Explain the issue.
2. Share screenshots or error logs.
3. Wait for clarification before changing unrelated code.

---

# 🎯 Goal

Our objective is to build a clean, scalable, and research-oriented application while following professional software engineering practices.

Happy Coding! 🚀
